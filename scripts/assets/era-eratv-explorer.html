ERA ERATV Explorer

Open an authorised vehicle type from ERA's ERATV knowledge graph (ERATV-KG on the UAT server) and read its values with one column per configuration, numbered as in ERATV, or put it next to a second type to see what differs. Find types with the fields of the ERATV advanced search: Type ID or name, authorisation document reference (EIN), category, manufacturer, conformity with TSI, Member State, status and dates. The page works from a snapshot when ERATV-KG cannot be read, and every query is written out as SPARQL, which you can read, copy, run live, or open in GraphDB.

Vehicle type

      

        
Matched against the Type ID, the type number, the alternative type name and the platform. ERATV-KG records no type name (ERATV field 1.1, rdfs:label) on any vehicle type, so the name shown in ERATV can only be found when it is also the alternative name or the platform.

      

      

      

        
ERATV-KG gives the category and subcategory concepts no label; the category names are ERATV's own, and the subcategories are named after their URI.

    


    

      
Manufacturer and authorisation holder

      

      

      

      

        
Every authorisation names its holder as an organisation role, …/organisationRoles/<number>_Manufacturer, that is described nowhere: not in ERATV-KG, nor in OCR-KG (UAT, PROD and dev) or ERADIS-KG (UAT and dev). So no holder has a name; the page does not show holders, and its snapshot carries none.

    


    

      
Conformity with TSI

      

        
Each configuration of a type records the TSIs it conforms to as the rdfs:label of its parameter set, worded as in ERATV, e.g. “CCS TSI (Regulation (EU) N° 2016/919) amended by Reg.(EU)2019/776”.

      

      

        
The certificates and declarations named by the authorisations (era:certificate) and by the type itself.

    


    

      
Authorisation

      

        
ERATV-KG publishes each type once per Member State, as …/vehicleTypes/<Type ID>-<Member State>. The Member State is read from that URI: era:authorisingMemberState is missing for the Netherlands (written “The%20Netherlands”) and for the types authorised by ERA (“EU”, ERATV's “Issued by ERA”).

      

        
The status of the current authorisation record. Its -Hn history entries, which carry the EINs, point back to it with era:canonicalUri.

    Data: the ERATV-KG repository on graph.uat.data.test-era.europa.eu (ERA's UAT server, which answers
    anonymous queries from any web page), graph http://data.europa.eu/949/graph/eratv. The page opens on a snapshot,
    era-eratv-snapshot.json.gz, built by scripts/build-eratv-snapshot.js with the page's own queries: the
    search index and every type's values per configuration, without authorisation holders, comments or notes. The search runs
    in the browser over it; “Run live” sends the SPARQL shown below to ERATV-KG and checks that it returns the same types. A
    vehicle type's values are queried live whenever ERATV-KG can be read, and come from the snapshot otherwise. Parameter names
    and ERATV numbers (era:eratvIndex) come from the ERA ontology release named in the source bar, then from
    ERATV-KG's graph/ontology; coded values from the release's SKOS, then graph/skos. The ERATV+ server
    (graph.tst.data.test-era.europa.eu) asks for a login, so the page does not use it yet; the type query already
    reads its graph layout and its era:hasVehicleTypeConfiguration. What the data does not say, the page does not invent:
    
    
      
  • no vehicle type carries a type name (rdfs:label, ERATV 1.1), and no authorisation holder resolves to an organisation;
    • 
      
  • the category and subcategory concepts, and most of the coded technical values, have no skos:prefLabel, in ERATV-KG or in the ontology release: they are shown by the end of their URI;
    • 
      
  • a parameter set's rdfs:label records its conformity with TSI, and is shown as such; ERATV-KG mints a configuration IRI per parameter set, so when two types are compared their configurations are paired by IRI where they share one (the Member-State copies of one Type ID) and by label otherwise;
    • 
      
  • the VPA properties are published in http://w3id.org/vpa# while the VPA classes are in https://w3id.org/vpa#, and addresses use http://w3.org/ns/locn#; the queries use the namespaces as published.
    • 
    

    ERATV itself remains the register of record.
