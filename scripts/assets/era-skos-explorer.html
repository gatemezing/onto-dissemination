ERA SKOS Explorer

Browses the SKOS concept schemes that govern ERA/RINF's controlled-vocabulary properties — things like operational point type, rail inclination or current type, each bound to a scheme via era:inSkosConceptScheme. Pick a scheme to see its concepts (notation, label, definition), switch between ERA's PROD and UAT vocabulary releases or compare them, then check PROD against what the live data actually uses: values present in the data but not declared as scheme members are exactly the kind of gap a malformed IRI or a mis-typed value creates — silently, since nothing in the endpoint validates a skos:ConceptScheme the way it validates a skos:Concept. Export to CSV or Excel. PROD and the usage check query graph.data.era.europa.eu live; UAT reads ERA's published UAT vocabulary file. Both go straight from your browser; nothing else is sent anywhere.

PROD and UAT are each fetched once as a single Turtle dump — PROD by CONSTRUCT over
       GRAPH <http://data.europa.eu/949/graph/rinf/skos> in rinf-plus (148 schemes,
       19,547 concepts; identical triple for triple to graph/skos in ERA-Onto), UAT from
       ERA's published era-vocabulary/era-skos file — parsed in the browser with
       N3.js, the same library and the
       same PROD/UAT split the SHACL Shape Viewer uses for ERA's shapes. Scoping every
       query to that one named graph, rather than the whole repository, is also what keeps the ontology's own
       resources — http://data.europa.eu/949/ itself is an owl:Ontology, not a concept —
       out of the scheme and concept lists; excluded a second time, defensively, by type.

    
Concept membership is checked three ways (skos:inScheme, skos:hasTopConcept,
       skos:topConceptOf), since ERA's datasets are not consistent about which one they publish. Labels
       prefer English but accept an untagged literal, the same gap found and fixed in the RCC Parameters and Route
       Book tools — some concepts here carry no language tag at all. Property-to-scheme bindings
       (era:inSkosConceptScheme) are read once from PROD and reused for UAT and Compare, since there is
       no published UAT ontology to read them from separately; the "check against real usage" panel only applies to
       PROD, since UAT describes a release that is not yet live data.

    
The "URI-pattern outlier" check flags concepts whose URI doesn't share the scheme's own dominant path prefix
       — the same shape of bug the reusability answers page found by
       hand for Operational Point Types: 8 concepts published at …/op-types/OperationalPointTypes/{n}
       instead of the scheme's own …/op-types/{notation}, with no skos:notation and
       Title-Case labels carrying typos. This tool surfaces that class of problem for every scheme with a bound
       property, not just that one — and now, with Compare, also surfaces which concepts UAT adds, drops or changes.
